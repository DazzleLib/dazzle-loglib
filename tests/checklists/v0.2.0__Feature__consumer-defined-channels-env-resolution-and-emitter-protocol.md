# Human Test Checklist: Consumer-Defined Channels, 10-Rung Re-Rung, Env Resolution, EmitterProtocol

**Target version:** dazzle-loglib 0.2.0
**Ships with commit:** TBD (first published release; extraction baseline was `4e8487d`)
**Companion automated tests:** 98 tests — tests/test_channel_registry.py (35), tests/test_log_verbosity.py (28), tests/test_resolve.py (14), tests/test_import_stability.py (11), tests/test_protocols.py (10)

## What this is

A hand-runnable verification pass for dazzle-loglib's first published release. It covers what the automated suite cannot: real terminal rendering of gated output on Windows codepages, actual DeprecationWarning visibility in a live interpreter, environment-variable behavior in real shells (three of them), and the feel of the consumer-declaration API a first-time adopter meets. Run it before tagging v0.2.0, and again for any release that touches `channels.py`/`manager.py`.

## Prerequisites

1. Python 3.9+ with `dazzle-lib>=0.8.0` installed; dazzle-loglib installed from the working tree (`pip install -e C:\code\dazzle-loglib`) or from PyPI post-release.
2. No configuration or dotfiles are touched by this library — no state isolation needed beyond a scratch directory for redirect tests.
3. Reset between sections: none required (the library is stateless across processes; each `python -c` starts fresh).

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these 5. Each is cross-shell safe as written (plain `python -c` one-liners).

### HV.1 — A program declares its own channels and they just work

Validates: the core 0.2.0 promise (LH-4) — consumer-defined channels with strict validation.

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, strict_channels=True, channel_defs=[ChannelDef('liveness','Liveness ladder')]); get_output().emit(1,'entry={e} -> reject({r})',channel='liveness',e='3dd1006f',r='missing-from-scan')"
  ```
- [ ] **Expected:** exactly `entry=3dd1006f -> reject(missing-from-scan)` on **stderr**, nothing on stdout, exit 0.
- [ ] **Why this matters:** if declaration, gating, or stderr routing is broken, every consumer integration (csb #87 first) is broken.

### HV.2 — Typo'd channel fails loud at DEFAULT verbosity

Validates: validate-before-gate (R1-F4) — the silent-typo trap is closed.

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=0, strict_channels=True, channel_defs=[ChannelDef('liveness')]); get_output().emit(5,'x',channel='livenes')"
  ```
- [ ] **Expected:** `ValueError: Unknown channel 'livenes'; known: [...]` — a traceback, NOT silence, even though level 5 would have been gated anyway.
- [ ] **Why this matters:** pre-0.2.0 this typo shipped silently and only exploded for the one user running `-vvvvv`.

### HV.3 — The 10-rung scale is live

Validates: the SD-FQCN-4 re-rung (SL-1): config=3, debug=5, named rungs in specs.

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import parse_channel_spec; from dazzle_loglib.verbosity import VERBOSITY_CONTINUUM as c; print(len(c.levels()), parse_channel_spec('scan:config').level, parse_channel_spec('scan:debug').level, parse_channel_spec('scan:diagnostics').level)"
  ```
- [ ] **Expected:** `10 3 5 2`
- [ ] **Why this matters:** the scale is locked API (docs/api-stability.md); the wrong map here means the published contract is wrong on day one.

### HV.4 — Env var respected when CLI is silent, beaten when CLI speaks

Validates: resolve precedence (LH-6) — the dazzlesum regression cannot recur.

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  set MYAPP_VERBOSITY=diagnostics
  python -c "from dazzle_loglib import resolve_verbosity; print(resolve_verbosity(0,0,env_var='MYAPP_VERBOSITY'), resolve_verbosity(1,1,env_var='MYAPP_VERBOSITY'))"
  set MYAPP_VERBOSITY=
  ```

  **PowerShell**:
  ```powershell
  $env:MYAPP_VERBOSITY = "diagnostics"
  python -c "from dazzle_loglib import resolve_verbosity; print(resolve_verbosity(0,0,env_var='MYAPP_VERBOSITY'), resolve_verbosity(1,1,env_var='MYAPP_VERBOSITY'))"
  Remove-Item Env:\MYAPP_VERBOSITY
  ```

  **POSIX**:
  ```bash
  export MYAPP_VERBOSITY=diagnostics
  python -c "from dazzle_loglib import resolve_verbosity; print(resolve_verbosity(0,0,env_var='MYAPP_VERBOSITY'), resolve_verbosity(1,1,env_var='MYAPP_VERBOSITY'))"
  unset MYAPP_VERBOSITY
  ```
- [ ] **Expected:** `2 0` — env's `diagnostics` (2) wins when nothing is expressed; `-v -q` (net 0, but EXPRESSED) beats the env.
- [ ] **Why this matters:** hook/scheduler diagnosability (csb #87 criterion) depends on env vars actually working; the historical bug silently discarded them.

### HV.5 — Legacy mutation warns; declared path is warning-clean

Validates: the deprecation shims (R1-F8 / AC-9).

- [ ] **Steps:**
  ```
  python -W error::DeprecationWarning -c "from dazzle_loglib import init_output, ChannelDef; init_output(channel_defs=[ChannelDef('a')]).emit(0,'clean',channel='a')"
  python -c "import warnings; warnings.simplefilter('always'); from dazzle_loglib import KNOWN_CHANNELS; KNOWN_CHANNELS.add('rogue')"
  ```
- [ ] **Expected:** first command prints `clean` and exits 0 (no warning became an error); second prints a `DeprecationWarning` naming `channel_defs=` and the removal version.
- [ ] **Why this matters:** the migration path must nudge loudly without punishing correct usage — that IS the shim policy.

## Section 1: Declaration semantics (~5 min)

### 1.1 Opt-in channels start cold and `--show` raises them

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=0, channel_defs=[ChannelDef('vals', opt_in=True)]); o=get_output(); print(o.channel_active('vals'))"
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=0, channel_defs=[ChannelDef('vals', opt_in=True)], channels=['vals']); o=get_output(); print(o.channel_active('vals'))"
  ```
- [ ] **Expected:** `False` then `True`.

### 1.2 Donor defaults do NOT leak into declared registries

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import init_output, ChannelDef; o=init_output(channel_defs=[ChannelDef('trace')]); print(o.channel_overrides)"
  ```
- [ ] **Expected:** `{}` — no `{'vals': -1, 'trace': -1}` donor residue; the declared hot `trace` follows global verbosity.

### 1.3 Contradictory declarations fail loudly

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import ChannelDef; ChannelDef('x', opt_in=True, default_level=2)"
  python -c "from dazzle_loglib import OutputManager, ChannelDef; OutputManager(channel_defs=[ChannelDef('a'), ChannelDef('a')])"
  ```
- [ ] **Expected:** `ValueError ... contradictory` and `ValueError ... duplicate ChannelDef 'a'`.

### 1.4 Channel listing shows YOUR channels with YOUR descriptions

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import OutputManager, ChannelDef; print(OutputManager(channel_defs=[ChannelDef('liveness','Session liveness verification'), ChannelDef('git','Git operations')]).format_channel_list())"
  ```
- [ ] **Expected:** an aligned two-column listing containing `liveness`, `git`, their descriptions, and the builtin service channels — NOT the donor's `parse`/`eval`/`vals` vocabulary. Eyeball the column alignment (a human check no assertion makes).

## Section 2: Output routing in a real terminal (~5 min)

### 2.1 Diagnostics go to stderr; stdout stays clean

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan')]); get_output().emit(1,'diag',channel='scan'); print('payload')" 1>%TEMP%\out.txt 2>%TEMP%\err.txt
  type %TEMP%\out.txt
  type %TEMP%\err.txt
  ```

  **PowerShell** (note: PS wraps native stderr; inspect the files, not the console):
  ```powershell
  cmd /c "python -c `"from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan')]); get_output().emit(1,'diag',channel='scan'); print('payload')`" 1>$env:TEMP\out.txt 2>$env:TEMP\err.txt"
  Get-Content $env:TEMP\out.txt
  Get-Content $env:TEMP\err.txt
  ```

  **POSIX**:
  ```bash
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan')]); get_output().emit(1,'diag',channel='scan'); print('payload')" 1>/tmp/out.txt 2>/tmp/err.txt
  cat /tmp/out.txt /tmp/err.txt
  ```
- [ ] **Expected:** `out.txt` contains only `payload`; `err.txt` contains only `diag`. This is the stdout-purity property csb's `--json` depends on.

### 2.2 A channel declared with `fd='stdout'` routes there

- [ ] **Steps:** repeat 2.1 replacing `ChannelDef('scan')` with `ChannelDef('scan', fd='stdout')`.
- [ ] **Expected:** `diag` now lands in `out.txt` (before `payload` or after — ordering between streams is unspecified; both lines present).

### 2.3 ASCII-only output on Windows terminals

- [ ] **Steps:** run 2.1 in a plain `cmd.exe` window (codepage 437).
- [ ] **Expected:** no mojibake, no `UnicodeEncodeError` — the library emits only what you pass it; confirm the library's own strings (warnings, error messages, channel listing) are pure ASCII.

## Section 3: The scale in practice (~3 min)

### 3.1 -v stacking walk

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import OutputManager; om=OutputManager(verbosity=4); print([om.is_level_active(n) for n in (1,2,3,4,5)])"
  ```
- [ ] **Expected:** `[True, True, True, True, False]` — at `-vvvv` (lite-debug) everything through 4 shows, full debug does not.

### 3.2 The hard wall still holds

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import OutputManager; om=OutputManager(verbosity=-4); om.error('you should not see me'); print('exit-code-only')"
  ```
- [ ] **Expected:** only `exit-code-only` — even errors are silent at the wall.

### 3.3 @trace fires only when the trace CHANNEL reaches full debug

(Corrected 2026-08-08 after the first tester run: the `trace` channel starts
opt-in-COLD on the legacy path, so a global `-vvvvv` alone does NOT activate
it — that is inherited, intended opt-in behavior, consistent with 1.1.)

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import init_output, trace; init_output(verbosity=5); f=trace(lambda x: x*2); print(f(3))"
  python -c "from dazzle_loglib import init_output, trace; init_output(channels=['trace:debug']); f=trace(lambda x: x*2); print(f(3))"
  ```
- [ ] **Expected:** first prints just `6` (trace stays cold even at `-vvvvv` on the legacy path); second prints `[TRACE] >> ...` / `[TRACE] << ...` lines around the `6`.

## Section 4: Injection contract (~2 min)

### 4.1 A print-shim satisfies the protocol at runtime

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib.protocols import EmitterProtocol, CallableEmitter, NullEmitter; from dazzle_loglib import OutputManager; print(isinstance(OutputManager(), EmitterProtocol), isinstance(CallableEmitter(print), EmitterProtocol), isinstance(NullEmitter(), EmitterProtocol))"
  ```
- [ ] **Expected:** `True True True`.

## What the automated tests DON'T cover

- Real terminal rendering: column alignment of `format_channel_list()`, codepage-437 behavior, stream interleaving order
- DeprecationWarning VISIBILITY in a live interpreter (tests assert emission; humans confirm users actually see them once, readably)
- Real shell env-var handling across cmd.exe / PowerShell / bash (tests monkeypatch `os.environ`)
- The first-adopter experience: is `ChannelDef` discoverable from the README alone? Does the ValueError text for a typo'd channel actually help?
- Performance feel of gated emits inside a genuinely hot loop (csb's liveness ladder is the real benchmark, at adoption)
- pythonw stream-rebind behavior (sentinels are unit-tested; the real `pythonw.exe` path is exercised at csb adoption)
