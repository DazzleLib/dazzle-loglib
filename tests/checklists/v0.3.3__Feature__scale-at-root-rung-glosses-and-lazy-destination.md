# Human Test Checklist: Scale at Root, Rung Glosses, and the Lazy Output Destination

**Target version:** dazzle-loglib 0.3.3
**Ships with commit:** TBD (`feat(0.3.3): export the locked verbosity scale at the package root; ship rung glosses as data`)
**Companion automated tests:** 103 tests — tests/test_channel_registry.py (36), tests/test_log_verbosity.py (28), tests/test_import_stability.py (15), tests/test_resolve.py (14), tests/test_protocols.py (10), plus tests/one-offs/check_cli_integration_recipe.py

## What this is

A hand-runnable pass over the release that first publishes this library to PyPI. Two things here genuinely need a human: the **rung glosses**, which exist to be *read* by users and can only be judged by reading them in a real terminal; and the **output-destination fix**, which changes which stream receives diagnostics and therefore behaves differently under shells, redirection, and `pythonw` than it does under pytest's capture.

Everything else in 0.3.3 is additive API covered by the suite. Run this before tagging, and again for any release that touches `manager.py`'s destination resolution.

## Prerequisites

1. Python 3.9+ with `dazzle-lib>=0.8.0` available; run from the repo root so `dazzle_loglib` imports from the working tree (or `pip install -e .`).
2. **No state isolation needed** — this library writes no config, touches no dotfiles, and creates no files. Only Section 3 writes scratch files, under the OS temp directory.
3. Reset between sections: none. Every step starts a fresh interpreter.

## High-Value Verification (~5 minutes)

### HV.1 — The scale imports from the package root

Validates: the fix at the centre of this release — `docs/api-stability.md` described the scale as part of the tracked surface while the root did not export it.

- [ ] **Steps** (cross-shell safe):
  ```
  python -c "from dazzle_loglib import VERBOSITY_CONTINUUM, shows, rank_of, verbosity_rungs, DEBUG, NOTHING; print('ok', rank_of('diagnostics'), DEBUG, NOTHING)"
  ```
- [ ] **Expected:** `ok 2 5 -4` — no `ImportError`.
- [ ] **Why this matters:** if this fails, the stability document points at symbols consumers cannot reach, which is the defect 0.3.3 exists to fix.

### HV.2 — The rung table reads well to a human

Validates: the glosses, which exist purely to be read. Tests can prove they are ASCII and non-empty; only a person can say whether they are *useful*.

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import verbosity_rungs; [print(f'  {r:+d}  {n:<12} {g}') for n,r,g in verbosity_rungs()]"
  ```
- [ ] **Expected:** ten rows, `-4` through `+5`, columns aligned, every gloss answering *what do I get at this level* (not what is suppressed).
- [ ] **Why this matters:** a consumer's `--help` renders these verbatim. If a gloss is confusing or inconsistent, it is confusing in every downstream tool.

### HV.3 — Diagnostics land on stderr, and stdout stays clean

Validates: the property machine-readable output depends on, in a real shell rather than under pytest capture.

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan','Scanning')]); get_output().emit(1,'diagnostic line',channel='scan'); print('PAYLOAD')" 1>%TEMP%\out.txt 2>%TEMP%\err.txt
  type %TEMP%\out.txt
  type %TEMP%\err.txt
  ```

  **PowerShell** (PowerShell wraps native stderr — inspect the files, not the console):
  ```powershell
  cmd /c "python -c ""from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan','Scanning')]); get_output().emit(1,'diagnostic line',channel='scan'); print('PAYLOAD')"" 1>$env:TEMP\out.txt 2>$env:TEMP\err.txt"
  Get-Content $env:TEMP\out.txt; Get-Content $env:TEMP\err.txt
  ```

  **POSIX**:
  ```bash
  python -c "from dazzle_loglib import init_output, get_output, ChannelDef; init_output(verbosity=1, channel_defs=[ChannelDef('scan','Scanning')]); get_output().emit(1,'diagnostic line',channel='scan'); print('PAYLOAD')" 1>/tmp/out.txt 2>/tmp/err.txt
  cat /tmp/out.txt; cat /tmp/err.txt
  ```
- [ ] **Expected:** `out.txt` contains only `PAYLOAD`; `err.txt` contains only `diagnostic line`.
- [ ] **Why this matters:** a consumer's `--json` mode must stay byte-identical at every verbosity. One stray diagnostic on stdout breaks every programmatic caller.

### HV.4 — The destination resolves late, not at construction

Validates: the behavior fix. The manager must not capture `sys.stderr` during `__init__`.

- [ ] **Steps:**
  ```
  python -c "import io,contextlib; from dazzle_loglib import OutputManager; om=OutputManager(verbosity=1); s=io.StringIO(); c=contextlib.redirect_stderr(s); c.__enter__(); om.emit(1,'captured'); c.__exit__(None,None,None); print('captured:', repr(s.getvalue())); print('default is the sentinel:', repr(om.file))"
  ```
- [ ] **Expected:** `captured: 'captured\n'` and `default is the sentinel: 'stderr'`. An empty capture means the old eager binding is back.
- [ ] **Why this matters:** this is what lets a `pythonw` host rebind streams after import, and what lets any test harness capture this library's output. It regressed silently once already.

### HV.5 — The documented recipe actually runs

Validates: `docs/cli-integration.md` end to end, since a recipe nobody executes rots.

- [ ] **Steps:**
  ```
  python tests/one-offs/check_cli_integration_recipe.py
  ```
- [ ] **Expected:** ends with `RESULT: PASS`; stdout is byte-identical across five verbosities; a malformed `--show` spec exits 2 rather than raising a traceback.
- [ ] **Why this matters:** the library ships no argparse code, so this document is the only specification of the wiring every adopter copies.

## Section 1: The scale as data (~3 min)

### 1.1 Ranks and names agree with the continuum

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib import verbosity_rungs, VERBOSITY_CONTINUUM as c; print(all(c.rank(n)==r for n,r,_ in verbosity_rungs()), len(verbosity_rungs()))"
  ```
- [ ] **Expected:** `True 10`.

### 1.2 Glosses survive a Windows console codepage

- [ ] **Steps** (Windows only; skip on POSIX):

  **cmd.exe**:
  ```cmd
  chcp 437
  python -c "from dazzle_loglib import verbosity_rungs; [print(g) for _,_,g in verbosity_rungs()]"
  ```
- [ ] **Expected:** ten lines, no `UnicodeEncodeError`, no mojibake — the glosses use `--` rather than an em dash for exactly this reason.

### 1.3 Deprecated alias still resolves

- [ ] **Steps:**
  ```
  python -c "from dazzle_loglib.levels import TIMING, EXTRA; print(TIMING == EXTRA == 1)"
  ```
- [ ] **Expected:** `True` — pre-0.2.0 code naming `TIMING` keeps working.

## Section 2: The charter wall (~1 min)

### 2.1 The library imports no argparse

- [ ] **Steps:**
  ```
  python -m pytest tests/test_import_stability.py::TestCharterWalls -q
  ```
- [ ] **Expected:** passes. This is an invariant guard — it cannot fail today; it fails the day someone adds parser construction to the library.
- [ ] **Optional (prove it fires):** append `import argparse` to any file in `dazzle_loglib/`, re-run, see it fail, then **undo the edit**.

## Section 3: Destination routing in a real shell (~5 min)

### 3.1 A channel declared to stdout goes to stdout

- [ ] **Steps:** repeat HV.3 replacing `ChannelDef('scan','Scanning')` with `ChannelDef('scan','Scanning',fd='stdout')`.
- [ ] **Expected:** `diagnostic line` now appears in `out.txt` alongside `PAYLOAD`. Ordering between the two streams is unspecified; both lines present is the pass condition.

### 3.2 Verbosity does not leak into stdout

- [ ] **Steps:** run HV.3's command at `verbosity=0`, `1`, `2`, `5`, comparing `out.txt` each time.
- [ ] **Expected:** `out.txt` is `PAYLOAD` every time; only `err.txt` grows.

### 3.3 (MANUAL, optional) pythonw rebinding

- [ ] **Steps:** in a script run under `pythonw.exe`, rebind `sys.stdout`/`sys.stderr` to a log file *after* importing the library and constructing a manager, then emit.
- [ ] **Expected:** output lands in the rebound file, not lost. **This step cannot be automated** — it needs the real `pythonw` host, where both streams start as `None`. Mark it skipped if you have no such harness; the unit test covers the mechanism, this covers the real host.

## What the automated tests DON'T cover

- **Whether the glosses are any good.** Tests prove they are ASCII, ten, and non-empty. Only a reader judges whether "Results only -- no hints" is clearer than what it replaced.
- **Real console rendering** — codepage 437/1252, column alignment at narrow widths, how the table looks next to a real `--help`.
- **Real shell redirection** (`1>`, `2>`) and PowerShell's native-stderr wrapping, which behave differently from pytest's capture.
- **The `pythonw` host** — the one place the destination fix matters most, and the one place only a human with that harness can confirm.
- **First-adopter experience:** is `verbosity_rungs()` discoverable from the README alone? Does `docs/cli-integration.md` answer the questions an adopter actually has, in the order they hit them?
- **Performance feel** of gated emits in a genuinely hot loop — the real benchmark arrives with the first consumer.
